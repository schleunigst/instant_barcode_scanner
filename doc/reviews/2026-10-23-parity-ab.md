## Findings fixed in this branch

| ID | Severity | Finding | Fix |
| --- | --- | --- | --- |
| P1 | Major | `switchCamera` switched the plugin's `selection` before the attempt; a failed/denied switch left the plugin on the new camera while the controller kept its old config, so the next drive silently opened the camera the caller believed it had not switched to. | Restore the previous selection on permission denial/failed snapshot; regression test in `controls_test.dart`. |
| P2 | Major | The scan window lived on the plugin and was not reset by `configure()`, so a new controller could inherit the previous session's restriction. | `configure()` clears `scanWindow`; per-controller lifetime now matches the controller doc. |
| P3 | Major | `setTorch`/`setZoom` bypassed the controller command queue, so they could interleave with `close`/`park`/`switchCamera` and update Dart state after the lifecycle changed. | Both now run through `_enqueue`, re-check `live` inside the queued action, and were covered by a call-order test. |
| P4 | Minor | `updateScanWindow` accepted NaN/Infinity because every bound comparison is false for NaN. | Reject non-finite rectangles with `ArgumentError`. |
| P5 | Minor | Pigeon host-method teardown list and mapping coverage omitted `updateScanWindow`/`analyzeImage`; the new mapping paths had only controller-level coverage. | Added both methods to teardown and added boundary tests for rect mapping and decoded-batch mapping (79→80 Dart tests). |
| P6 | Minor | `toggleTorch` doc said "no-op when no flash" while the implementation throws `unsupported`. | Documentation corrected; the explicit exception is the documented contract. |

## Remaining observations (not changed)

- `analyzeImage` closes its ML Kit client in `finally`; if the Dart call is
  cancelled mid-process the native task may still be running. ML Kit's client
  close is safe, and callers cannot observe a result after cancellation.
- `invertImage` allocates one NV21 copy per analyzed frame (about 1.4 MB at
  720p). It is opt-in; a reusable buffer would race in-flight ML Kit tasks and
  was not worth the complexity.
- `switchCamera` resets the torch and zoom; this is the documented controller
  contract (`config.initialTorch` is not re-applied), not a bug.
- Lens preference is a focal-length heuristic. Multi-camera selection and
  front-camera availability still need a physical device; the emulator has a
  single emulated back camera.
- `invertImage` is Android-only and silently ignored by platforms that do not
  implement it (documented). No capability bit was added to keep
  `ScannerCapabilities` stable.
